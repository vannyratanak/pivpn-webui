Add forward / drop rule

Controls what's allowed through the FORWARD chain — e.g. drop a subnet, or explicitly accept traffic between two ranges.

Add INPUT rule

Controls what's allowed to reach this server itself (its web UI, SSH, anything listening here) — not traffic passing through it to somewhere else, that's the FORWARD rule above. A rule that would block your own current connection is refused rather than applied.

Add port-forward rule

DNAT: forward an external port to a VPN client's internal IP.

Add SNAT rule

Like the automatic outbound NAT, but with a fixed exit IP instead of whatever address the outgoing interface currently has.

Import rules from file

One rule per line: kind key=value key=value .... Blank lines and lines starting with # are ignored. Quote values with spaces, e.g. comment="block guest wifi".

KindFieldsExample line
forward action, protocol, src, dst, dport, comment forward action=DROP protocol=tcp src=10.8.0.5 dst=192.168.1.0/24 dport=443
portforward ext_port*, target_ip*, target_port, protocol, ext_iface, comment portforward ext_port=8080 target_ip=10.8.0.5 target_port=80 protocol=tcp
snat src, snat_ip*, out_iface, comment snat src=10.202.226.0/24 snat_ip=192.168.100.12 out_iface=ens19 comment="cluster access"

* required. Any field can be left out where the "Add ___ rule" forms above also allow it blank.

Reusable template: a line NAME=value (no rule kind) defines a variable — reference it as $NAME in any rule line after it. E.g. put CLIENT_IP=10.202.226.21 at the top, then use src=$CLIENT_IP in every rule below.

A rule's src/dst can also just be a VPN client's name instead of an IP — e.g. src=nurak resolves to that client's current VPN IP automatically.

Lines can also be raw iptables -A FORWARD ... / -A INPUT ... commands instead of kind key=value syntax — an existing shell script's rule lines can be uploaded close to verbatim ($VAR and client-name resolution both still apply). Non--A lines (e.g. a "clean old rules" -S | grep | ... -D pipeline) are skipped, not an error — this app's own rule sync already replaces the need for that cleanup step.
