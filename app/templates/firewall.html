Add forward / drop rule

Controls what's allowed through the FORWARD chain — e.g. drop a subnet, or explicitly accept traffic between two ranges.

Add INPUT rule

Controls what's allowed to reach this server itself (its web UI, SSH, anything listening here) — not traffic passing through it to somewhere else, that's the FORWARD rule above. A rule that would block your own current connection is refused rather than applied.

Add port-forward rule

DNAT: forward an external port to a VPN client's internal IP.

Add SNAT rule

Like the automatic outbound NAT, but with a fixed exit IP instead of whatever address the outgoing interface currently has.

Import rules from file

Upload a plain text file to add several firewall rules at once — one rule per line.

  • Each line looks like kind key=value key=value ... — start with the rule's kind (see the table below), then its fields as key=value pairs.
  • Blank lines, and lines starting with #, are skipped — use # to leave yourself notes.
  • If a value has spaces in it, wrap it in quotes, e.g. comment="block guest wifi".
KindFieldsExample line
forward action, protocol, src, dst, dport, comment forward action=DROP protocol=tcp src=10.8.0.5 dst=192.168.1.0/24 dport=443
input action, protocol, src, dport, comment input action=DROP protocol=tcp dport=22
portforward ext_port*, target_ip*, target_port, protocol, ext_iface, comment portforward ext_port=8080 target_ip=10.8.0.5 target_port=80 protocol=tcp
snat src, snat_ip*, out_iface, comment snat src=10.202.226.0/24 snat_ip=192.168.100.12 out_iface=ens19 comment="cluster access"

* means that field is required. Any other field can be left blank, same as on the "Add ___ rule" forms above.

A few shortcuts that also work:

  • Reusable values. A line with just NAME=value (no rule kind) defines a variable you can reuse below. E.g. put CLIENT_IP=10.202.226.21 at the top of the file, then use src=$CLIENT_IP in any rule line after it.
  • Client names instead of IPs. For src/dst, you can type a VPN client's name instead of its IP — e.g. src=nurak automatically resolves to that client's current VPN IP.
  • Paste from an existing script. Lines can also be raw iptables -A FORWARD ... / -A INPUT ... commands instead of kind key=value syntax — an existing shell script's rule lines can be uploaded almost as-is (variables and client names above still work on these too). Any other kind of line, like a "clean up old rules" pipeline, is silently skipped rather than treated as an error — this app's own rule sync already replaces the need for that cleanup step.
